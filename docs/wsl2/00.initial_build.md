# Initial Host-Only Build & Smoke Test

This document captures the exact steps and observations from the first
successful host-side build of the IAOO Toolkit, using only the native x86_64
toolchain plus vendored `libelf` bits already present in the repository.

## Prerequisites

- Verified tool versions (run from the repo root `/home/rai_s/iato`):

```
cmake --version    # 3.31.6
g++ --version      # gcc 14.2.0
ldconfig -p | grep libelf   # confirms a system libelf runtime is visible
```

- Cross IA64 toolchains are **not** required because the sample binaries under
  `misc/` are precompiled.
- `misc/` already contains the extracted artifacts from the two tarballs listed
  in `README.md`:
  - `misc/clt` ← contents of `iato-tst-1.5.tar.gz` (small IA64 programs/tests)
  - `misc/spec` ← contents of `iato-spec-2000.tar.gz` (SPEC2000 IA64 suites)

## Vendored `libelf` Setup

System headers were missing, so the Debian packages were downloaded and
unpacked locally (no sudo required):

```
apt-get download libelf-dev libelf1t64
mkdir -p third_party/libelf
dpkg -x libelf-dev_0.192-4_amd64.deb third_party/libelf
dpkg -x libelf1t64_0.192-4_amd64.deb third_party/libelf
rm libelf-dev_0.192-4_amd64.deb libelf1t64_0.192-4_amd64.deb
```

`third_party/libelf/usr/include` now holds `libelf.h`/`gelf.h`, and
`third_party/libelf/usr/lib/x86_64-linux-gnu` exposes `libelf.so.1`.  No PATH
changes are required because the CMake configuration below embeds the absolute
library path. (Confirm with `ldd build/bin/iaos | grep libelf`.)

## Configure

All build products live under `build/`.  Regenerate with:

```
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release \
  -DElf_INCLUDE_DIR=/home/rai_s/iato/third_party/libelf/usr/include \
  -DElf_LIBRARY=/home/rai_s/iato/third_party/libelf/usr/lib/x86_64-linux-gnu/libelf.so
```

The top-level `CMakeLists.txt` pulls in `src/lib`, `src/clt`, and `tst`.
Configuration warnings about `cmake_minimum_required` are harmless for 3.31.

## Build

```
cmake --build build --target iaos t_bundle
```

This target list builds the core static libraries plus:

- `build/bin/iaos` – static analyzer client
- `build/bin/t_bundle` – ISA bundle regression test

## Code Fixes Applied

Modern glibc headers define short macros such as `NAT`, `NEG`, and `ZERO`,
colliding with the historical `t_fpclass` enum in `src/lib/isa/Opcode.hpp`.
The build was unblocked by undefining those macros immediately before the enum
definition (see the file for the exact block).

## Example Runs

1. **Static analysis of a small IA64 program**

   ```
   ./build/bin/iaos -e -d misc/clt/pgm/p_0001 | head -n 200
   ```

   Output shows ELF metadata (file type, entry point, load segments) followed by
   the first ~200 lines of disassembly.  The pipeline exits with code 141
   because `head` closes the pipe after consuming 200 lines; running without
   `head` provides the full disassembly and statistics.

2. **Unit sanity check**

   ```
   ./build/bin/t_bundle
   ```

   No output indicates all assertions in `tst/lib/isa/t_bundle.cpp` passed.

## Next Steps / Notes

- Larger workloads (e.g., `misc/spec/CINT2000/256.bzip2/bzip2_ia64`) can be
  analyzed by swapping the path in the `iaos` invocation above.
- Keep `third_party/libelf` under version control or add automation to fetch it,
  since both the build and the resulting binaries depend on those files.

## Full Client Build (IAOS/IAKA/IAIO/IAOO/IATA)

**Date:** 2025-11-26

Purpose: build every client mentioned in `README.md` with the host-only toolchain
and capture a quick sanity run for each.

### Additional build-system tweaks

- `src/clt/CMakeLists.txt` now adds the missing `iaio` subdirectory so the
  in-order simulator participates in CMake builds.
- `src/clt/iaio/CMakeLists.txt` was rewritten to mirror the historic Makefile:
  all stage/source files are listed explicitly, and the target is linked against
  `iaisa`, `iaelf`, `iakrn`, `iamac`, `iaecu`, and `Elf::elf`.
- The `t_fpclass` macro undefines in `src/lib/isa/Opcode.hpp` (see above) remain
  required for modern glibc toolchains.

Reconfigure & build everything from the repo root:

```
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release \
  -DElf_INCLUDE_DIR=/home/rai_s/iato/third_party/libelf/usr/include \
  -DElf_LIBRARY=/home/rai_s/iato/third_party/libelf/usr/lib/x86_64-linux-gnu/libelf.so

cmake --build build --target iaos iaka iaio iaoo iata
```

Artifacts land in `build/bin/`.

### Smoke tests

Each run executed from `/home/rai_s/iato`; outputs captured in `build/*.log`.

| Client | Command | Result |
| --- | --- | --- |
| IAOS | `./build/bin/iaos -e misc/clt/pgm/p_0001 \| head -n 40` | Prints ELF metadata for the sample binary (see log excerpt above). |
| IAKA | `./build/bin/iaka -s -m 1000 misc/clt/pgm/p_0001 &> build/iaka_p0001.log` | Emits bundle/instruction statistics and exits 0. |
| IAIO | `./build/bin/iaio -s -m:i 1000 misc/clt/pgm/p_0001 &> build/iaio_p0001.log` | Produces IPC/cycle statistics (sample shown below) and exits 0. |
| IAOO | `./build/bin/iaoo -m:i 2000 misc/clt/pgm/p_0001 &> build/iaoo_p0001.log` | Starts execution but traps with a “data access rights fault” when the binary dereferences `0x0`. Fault details recorded in the log; indicates simulator is running but the program needs more complete OS emulation. |
| IATA | `./build/bin/iata -h` | Usage text displayed (sufficient without a trace file). |

### Verification & Observations

- **Binary presence**: `ls build/bin/{iaos,iaka,iaio,iaoo,iata}` confirms each client executable exists post-build.
- **Runtime logs**: text outputs are persisted under `build/` so they can be inspected without rerunning:
  - `build/iaka_p0001.log` – bundle and instruction stats from the emulator run.
  - `build/iaio_p0001.log` – IPC and flush statistics from the in-order simulator.
  - `build/iaoo_p0001.log` – the out-of-order simulator fault report (see below).
- **Return codes**: IAOS/IAKA/IAIO/IATA return `0`; IAOO returns `1` with the expected fault diagnostics, verifying the simulator is active even though the bare binary lacks an OS shim.
- **Libelf linkage**: `ldd build/bin/iaos | grep libelf` shows every client is dynamically linked against the vendored `third_party/libelf` copy, so no system installation is required.
- **Repeatability**: rerunning `cmake --build build --target iaos iaka iaio iaoo iata` after a `git clean -fdx build` reproduces the same binaries because all inputs (vendored `libelf`, `misc/` binaries, CMake files) live inside the repo.

The IAOO fault log currently reads:

```
error   : interrupt
reason  : data access rights fault at 0x0000000000000000 at 0x4000000000000270 slot 0

```

This is expected when running bare-metal IA64 binaries without an OS shim;
future work could map additional segments or use the sample traces provided in
`misc/spec`.
