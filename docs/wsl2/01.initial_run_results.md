# IA64 Verification Matrix

This document captures the end-to-end verification of every IA64 binary already
unpacked under `misc/` (both the `clt` samples and the SPEC2000 workloads) using
the five IATO clients. All commands were executed from `/home/rai_s/iato`.

## Inputs & automation

- **Manifest**: `build/manifest/misc_ia64_binaries.json` (142 binaries, produced
  by `python3` scan in this session).
- **Criteria**: `misc/verification/criteria.json` defines what “success” means
  per client.
- **Harness**: `scripts/run_iato_matrix.py` iterates over the manifest,
  dispatches each client, collects logs under `build/logs/<client>/`, and (for
  IAKA) emits traces to `build/traces/iaka/`.

Example invocation that produced the final matrix:

```
# Analyze binaries & generate traces
./scripts/run_iato_matrix.py --clients iaos,iaka,iaio,iaoo --categories clt,spec --emit-traces

# Feed IATA with IAKA traces
./scripts/run_iato_matrix.py --clients iata --categories clt,spec --iata-trace-source iaka
```

Summaries for each client live at `build/logs/<client>/summary.json`.

## Log & trace locations

- `build/logs/iaos/…` : ELF metadata/disassembly output (one log per binary).
- `build/logs/iaka/…` : Emulator stats + trace file path; errors cite the
  interrupt reason.
- `build/logs/iaio/…` : In-order simulator stats or trap reason.
- `build/logs/iaoo/…` : Out-of-order simulator stats or OS fault reason.
- `build/logs/iata/…` : Trace parsing failures (“invalid trace header”).
- `build/traces/iaka/…` : Binary traces emitted by IAKA (usable for future
  tooling once the decoder is updated).

## Known issues & follow-ups

1. **IAKA/IAIO unimplemented instructions**  
   Several ISA feature tests (`misc/clt/isa/F13`, `M36`, etc.) still exercise
   opcodes that the emulator/simulators treat as “unimplemented.” These failures
   are localized and documented in the corresponding logs.

2. **IAOO OS faults**  
   IAOO stops almost immediately on SPEC programs because they execute syscalls
   or dereference unmapped memory (e.g., load via `r11` at address `0x0`). This
   is expected absent a kernel shim; capturing the precise fault was the goal.

3. **IATA trace compatibility**  
   Every IATA invocation fails with:

   ```
   error  : tracer-error
   reason : invalid trace header from file <trace>
   ```

   The trace generator (IAKA 1.5) and analyzer (IATA 1.5) disagree on header
   format when built with this modern toolchain. Next steps: compare emitted
   trace headers with the format expected by `misc/iato-ref-1.5.pdf`, or patch
   IATA to handle the observed header.

4. **SPEC binaries exit quickly**  
   The harness caps instruction/cycle counts (6k for SPEC) to avoid multi-minute
   runs. This verifies startup paths, but not full benchmark completion. Adjust
   `scripts/run_iato_matrix.py` limits if deeper coverage is required.

## Reproduction checklist

1. Ensure `build/bin/{iaos,iaka,iaio,iaoo,iata}` exist (run CMake build as in
   `misc/00.initial_build.md`).
2. Generate/refresh the manifest:  
   `python3 - <<'PY' ...` (see session history) or keep the committed JSON.
3. Run the harness commands above (passing `--emit-traces` when invoking IAKA).
4. Review `build/logs/<client>/summary.json` for counts; inspect individual logs
   for failure reasons.
5. Optional: tweak client flags or limits by editing `scripts/run_iato_matrix.py`
   (`CLIENT_CONFIG` block) and re-run.
