# Heap / `brk` Scaffolding Fix

## 1. Objective

Ensure IAOO always maps an initial heap (and guard page) so IA64 programs that
call `brk`/`br.m` no longer dereference address `0x0`. This follows the plan in
`build.plan.md` (“Heap/brk Scaffolding Fix”).

## 2. Baseline Behavior

Before any changes, `misc/clt/isa/M01` faulted immediately after its first
`br.m` because the loader never created a data segment:

```
$ ./build/bin/iaoo -s -m:i 20000 -m:c 20000 misc/clt/isa/M01
error   : interrupt
reason  : data access rights fault at 0x0000000000000000 at 0x40000000000000b0 slot 0
opcode  : ld8 r3=[r3]
```

The `build/logs/iaoo/misc__clt__isa__M01.log` file carried the same message
during automation runs.

## 3. Investigation

1. **Audit loader state**  
   - Reviewed `ElfExec`, `ElfMap`, `ElfBrk`, and `System`.  
   - Findings:
     - `ElfImage::getbrkm()` cloned PT_LOAD segments into an `ElfBrk`, but no
       code called `setbrkta()` or mapped any additional pages.
     - `System` and `Syscall` APIs had no way to report/query the current break.

2. **Locate heap start**  
   - `readelf -l misc/clt/isa/M01` showed the binary maps a single PT_LOAD from
     `0x4000_0000_0000_0000` to `+0x1b0`. Anything beyond that address is
     unmapped unless `brk` grows it.

3. **Decide fix scope**  
   - Pre-map at least one heap page immediately after the last PT_LOAD.  
   - Track heap base/limit so `krn_brk` can extend it page-by-page and keep a
     guard page.

## 4. Implementation Details

### 4.1 `ElfBrk`

Files: `src/lib/elf/ElfBrk.cpp`, `ElfBrk.hpp`

- Added bookkeeping fields `d_heapb`, `d_guard`, accessors, and `bootstrap()`.
- Updated `setbrkta()` to:
  - Align requested addresses to page boundaries.
  - Prevent shrinking below the initial heap base.
  - Allocate new `ElfSegment`s one page at a time with RW protection, keeping
    `d_guard = d_brkta + page_size`.
- `addseg()` now updates `d_heapb/d_guard` when PT_LOAD segments extend higher.

### 4.2 Loader bootstrap

File: `src/lib/elf/ElfImage.cpp`

- After calling `exim->setbrkm(getbrkm())`, invoke `brkm->bootstrap()` so the
  process starts with at least one mapped heap page before executing guest code.

### 4.3 System exposure

Files: `src/lib/mac/System.hpp/.cpp`

- Added `getbrkva()` so other components (e.g., syscall handlers or future OS
  scaffolding) can query the current break without spelunking through `ElfExec`.

## 5. Verification

1. **Rebuild everything**
   ```
   $ cmake --build build
   ```
   (All libraries and clients rebuilt successfully.)

2. **Re-run `misc/clt/isa/M01`**
   ```
   $ ./build/bin/iaoo -s -m:i 20000 -m:c 20000 misc/clt/isa/M01
   error   : interrupt
   reason  : data access rights fault at 0x0000000000000000 at 0x40000000000000f0 slot 0
   opcode  : ld8 r5=[r1]
   ```

   The failure moved from `ld8 r3=[r3]` (heap) to `ld8 r5=[r1]` (stack/global
   pointer), demonstrating that heap pages are now present while stack/TLS
   scaffolding remains outstanding.

3. **Documentation update**  
   Added the new observation and log snippet to
   `misc/verification/02.missing-features.md` so future work can focus on the
   stack/argv/TLS gap.

## 6. Remaining Work

- Implement stack/argv/TLS initialization so `r1/r12/r13` point to valid frames.
- Teach syscall handlers (`krn_brk`, `krn_mmap`, `krn_mmap`-backed allocations)
  to use `System::getbrkva()` and support more dynamic growth scenarios.
- Add regression tests (e.g., scripted `run_iato_matrix` subset) once the stack
  scaffolding lands to ensure heap regressions are caught automatically.
