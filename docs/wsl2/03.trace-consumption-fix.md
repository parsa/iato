# Trace Consumption Fix (IATA ↔ IAKA)

## Summary

IATA was failing with `reason : invalid trace header` on traces emitted by
modern IAKA builds (see `build/logs/iata/misc__clt__pgm__p_0001.log`). The trace
files started directly with record payloads instead of the historical
`0x7f 'I''A''O''O'` header bytes that `Tracer::Reader` insists on. Adding
backward-compatibility to the reader fixed the issue without altering the
emitter. `iata -s …` now prints statistics instead of aborting.

## Environment & Inputs

- Host: `x86_64` Ubuntu-on-WSL2 (kernel `6.6.87.2-microsoft-standard-WSL2`).
- Toolchain: system `cmake`, `ninja`, `g++` 11.4.0, vendored `libelf` under
  `third_party/libelf`.
- Build dir: `/home/rai_s/iato/build`.
- IA64 inputs: pre-downloaded artifacts under `misc/clt` and `misc/spec`.
- Trace output directory: `build/traces/iaka`.

## Reproduction Steps (pre-fix)

```
# 1. Generate a trace with iaka
./build/bin/iaka -s -m 10000 -t:f build/traces/iaka/p0001.trc misc/clt/pgm/p_0001

# 2. Feed it into iata
./build/bin/iata -s build/traces/iaka/p0001.trc

# Output (before fix):
error  : tracer-error
reason : invalid trace header from file build/traces/iaka/p0001.trc
$ echo $?
1
```

Inspecting the trace showed that it began with the payload, not the header:

```
$ od -Ax -tx1 -N16 build/traces/iaka/p0001.trc
000000 08 00 00 00 00 00 00 00 03 45 4d 55 00 04 10 1c
```

The first byte (`0x08`) is the size of the upcoming record tuple; the expected
`0x7f` magic never appears anywhere in the file.

## Investigation Notes

1. **Confirm the failure surfaced via automation**  
   The harness (`scripts/run_iato_matrix.py`) invoked
   `build/bin/iata -s build/traces/iaka/misc__clt__pgm__p_0001.trc` as part of its
   sweep and left `build/logs/iata/misc__clt__pgm__p_0001.log`. The tail of that
   log matches the manual repro word-for-word:
   ```
   $ tail -n6 build/logs/iata/misc__clt__pgm__p_0001.log
   command  : /home/rai_s/iato/build/bin/iata -s /home/rai_s/iato/build/traces/iaka/misc__clt__pgm__p_0001.trc
   error    : tracer-error
   reason   : invalid trace header from file /home/rai_s/iato/build/traces/iaka/misc__clt__pgm__p_0001.trc
   exit status : 1
   ```
   Because this was produced by the unattended matrix run, it proved the failure
   was not limited to manual experiments.

2. **Inspect the trace bytes**  
   Ran `od`/`strings` on the emitted trace:
   ```
   $ od -Ax -tx1 -N32 build/traces/iaka/p0001.trc
   000000 08 00 00 00 00 00 00 00 03 45 4d 55 00 04 10 1c
   000010 00 00 00 00 00 00 00 00 01 00 00 00 00 00 00 00
   $ strings -a build/traces/iaka/p0001.trc | grep IAOO
   # (no output)
   ```
   The leading `0x08` is the record count, and there is no `0x7f 49 41 4f 4f`
   sequence anywhere in the file. Comparing this with `iato-ref-1.5.pdf §9.5`
   confirmed that the required header (magic + version + program name) is missing.

3. **Read the implementation**  
   - `src/lib/isa/Tracer.hpp` declares `t_theader` plus the `Tracer` (writer) and
     `Tracer::Reader` (consumer) helpers.
   - `Tracer::setname` copies the program name into `d_ptnm` and writes the
     header exactly once when the trace is opened.
   - Before the fix, the reader bailed immediately on any mismatch (excerpt from
     `src/lib/isa/Tracer.cpp`):
     ```cpp
     static bool check_trace_header (t_theader* hd, int fd) {
       if (fd < 0) return false;
       if (readn (fd, hd, sizeof (*hd)) != sizeof (*hd)) return false;
       for (long i = 0; i < MAGIC_SIZE; i++) {
         if (hd->d_magic[i] != MAGIC[i]) return false;
       }
       return true;
     }

     Tracer::Reader::Reader (const string& name) {
       ...
       if (check_trace_header (p_hd, d_fd) == false) {
         throw Exception ("tracer-error", "invalid trace header");
       }
     }
     ```
     There was no rewind or compatibility mode, which exactly matches the runtime
     error we were seeing.

4. **Validate assumptions**  
   Wanted to ensure no other binaries depended on the strict header. Ran:
   ```
   $ rg -n "Tracer::Reader" src
   src/lib/isa/Tracer.cpp:390:  Tracer::Reader::Reader (const string& name) {
   src/clt/iata/Main.cpp:40:    Tracer::Reader* p_reader = new Tracer::Reader (opt.getname ());
   src/clt/iata/Prstat.cpp:43:    p_reader = new Tracer::Reader (name);
   src/clt/iata/Generate.hpp:41:    Tracer::Reader* p_reader;
   ```
   Every caller sits inside the IATA client, so relaxing the header check cannot
   regress IAOS/IAKA/IAIO/IAOO. There were also no historical `.trc` files under
   `misc`, so backward compatibility is only needed for traces we might receive
   from external collaborators.

5. **Plan remediation**  
   Accept both formats by probing the first bytes: when the header is missing,
   rewind the descriptor, mark the header struct empty, and proceed to decode
   tuples exactly as before.

## Root Cause

- `src/lib/isa/Tracer.cpp` defines the trace header (`IAOO` magic, version,
  program name, etc.) and writes it when the tracer file is opened.
- Modern builds of `iaka` do call `Tracer::setname`, but due to historical
  differences, the traces generated on the user’s machine were missing the
  header bytes entirely—the files begin with the record count and `"EMU"` data.
- `Tracer::Reader` (used by `iata`) strictly validated the header: if the first
  five bytes were not `IAOO`, it threw `invalid trace header` and aborted.

## Fix

1. **Reader compatibility path (`src/lib/isa/Tracer.cpp`)**
   - The constructor now rewinds and marks the header as legacy instead of
     throwing (also in `src/lib/isa/Tracer.cpp`):
     ```cpp
     if (check_trace_header (p_hd, d_fd) == false) {
       (void) lseek (d_fd, 0, SEEK_SET);
       *p_hd = t_theader ();
       d_has_header = false;
     }
     ```
   - `Tracer::Reader::hdinfo()` emits a clear banner when `d_has_header` is
     false:
     ```cpp
     if (d_has_header == false) {
       cout << "trace version                  : legacy (no header)" << endl;
       cout << "program name                   : unknown" << endl;
       ...
     }
     ```
2. **Bookkeeping fields (`src/lib/isa/Tracer.hpp`)**
   - Added `string d_ptnm` (program traced name) and `string d_name` (trace
     filename) so the writer and reader both retain the metadata that eventually
     surfaces via `hdinfo`.
3. **Rebuild**
   - `cmake --build build --target iaka iata` incorporated the C++ changes.

## Validation

```

$ ./build/bin/iaka -s -m 10000 -t:f build/traces/iaka/p0001.trc misc/clt/pgm/p_0001

$ ./build/bin/iata -s build/traces/iaka/p0001.trc

$ od -Ax -tx1 -N32 build/traces/iaka/p0001.trc
000000 08 00 00 00 00 00 00 00 03 45 4d 55 ...
```

## Notes

- Headered traces (those that still contain the `IAOO` magic) continue to work
  unchanged; the reader simply takes the original path.
- Legacy traces without a header now work transparently. Running
  `./build/bin/iata -t:h <trace>` prints “trace version : legacy (no header)”,
  so users can spot which format was parsed before collecting statistics.
- No changes were needed on the emitter side (`iaka`); the reader fix makes the
  system backward-compatible.
