# Apple Silicon Porting & Verification Notes

This log captures the exact steps and observations for getting IATO to build
and run on an Apple Silicon (arm64) macOS 15.1 machine, including the code
changes we landed, the commands we executed, and how to reproduce/verify
the results from scratch.

> **Host details**
>
> - Hardware: Apple Silicon (M4-class)  
> - OS: macOS 15.1 (25.1.0)  
> - Toolchain: Apple clang 17.0.0, CMake 4.2.0, Ninja 1.11.1, Homebrew 5.0.3  
> - Shell: `/bin/zsh`

---

## 1. Environment Preparation

1. Install Xcode Command Line Tools (if not already installed):

   ```bash
   xcode-select --install
   ```

2. Install required Homebrew packages:

   ```bash
   brew install cmake ninja pkg-config libelf
   ```

3. Ensure the Homebrew paths are exported (typical on Apple Silicon):

   ```bash
   export PATH="/opt/homebrew/bin:$PATH"
   export CPATH="/opt/homebrew/include:$CPATH"
   export LIBRARY_PATH="/opt/homebrew/lib:$LIBRARY_PATH"
   ```

4. Clone or update the IATO repository, then check out the
   `feat/process-image-setup` branch (or your working branch).

---

## 2. Code Changes for macOS Support

The following updates were committed (see
`onboard apple silicon and kernel flag regression test`, SHA `e9804eb`):

- `CMakeLists.txt`
  - Require CMake ≥ 3.5.
  - Detect `APPLE` and define `OS_DARWIN IATO _REENTRANT HAS_PTHREAD`.
  - `find_package(Threads REQUIRED)` so pthreads link correctly.
- `cmake/FindElf.cmake`
  - Integrate `pkg-config` and Homebrew search paths (`/opt/homebrew`).
  - Create an imported `Elf::elf` target that exposes both `libelf` include
    directories (the Homebrew formula nests headers under `libelf/`).
- ISA, ELF, and kernel headers (`src/lib/{isa,elf,krn}`) now gate POSIX
  includes on `#if defined(OS_LINUX) || defined(OS_DARWIN)`.
- `KrnIoctl`
  - Use `tcgetattr()` on macOS (no `TCGETS`), guard non-portable
    `termios::c_line`.
- `KrnFcntl`
  - Add an `OS_DARWIN` block that maps Linux open/fcntl flags (including
    `KRN_O_DIRECTORY`, `KRN_O_NOFOLLOW`, `KRN_O_LARGEFILE`, etc.).
- Added a regression test suite `tst/lib/krn` with `t_open_flags.cpp`
  to ensure the flag mapping preserves Linux semantics (the test uses
  `open()` with `KRN_O_DIRECTORY` and asserts `ENOTDIR`).
- Authored `BUILD_MACOS.md` documenting the general build instructions
  (Kept as a high-level companion; this doc contains the detailed log).

## 3. Clean Build & Tests

All commands below were run from the repository root.

```bash
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build
ctest --test-dir build
```

The final `ctest` run reported:

```
15/15 tests passed
Total Test time (real) = 2.28 sec
```

Notable tests include the new `tst.lib.krn.t_open_flags`, which confirms that
`KRN_O_DIRECTORY` still produces an `ENOTDIR` error when mapped through the
Darwin shim—preventing silent regressions on non-Linux hosts.

## 6. Reproducing the Kernel Flag Regression Test Manually

For reference, the regression test validates that `KRN_O_DIRECTORY`
translations still cause `open()` to fail on regular files.

To run it directly:

```bash
./build/bin/t_open_flags
```

You can also exercise the logic manually:

```bash
# Linux flag constants (KRN_O_DIRECTORY, etc.) are defined in KrnFcntl.hxx
./build/bin/iaos misc/clt/pgm/p_0001             # ensures binary loads
```

The core of the test is:

```c++
const t_octa linux_flags = KRN_O_RDONLY | KRN_O_DIRECTORY;
const t_octa host_flags  = map_open_flags(linux_flags);
int fd = ::open(path, static_cast<int>(host_flags));
assert(fd == -1);
assert(errno == ENOTDIR);
```

## 7. Verification Checklist

To reproduce or verify this port on another Apple Silicon Mac:

1. Install toolchain dependencies (Section 1).
2. Check out the branch containing the macOS changes.
3. Run the build + unit tests (Section 3).
4. Execute the client smoke tests (Section 4).
5. Run at least one sample from `misc/clt` and one SPEC binary from
   `misc/spec` (Section 5) to confirm end-to-end functionality.
6. Optionally rerun the regression test suite:

   ```bash
   ctest --test-dir build
   ```

Everything described above was executed on the recorded host and is known
to succeed with the committed code. If you deviate (different compiler,
older macOS, missing Homebrew packages), revisit the dependency setup
before debugging build/runtime issues.
