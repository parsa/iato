# Missing Instructions Implementation

## Context
During the initial run of the `iato` test suite on macOS (and Linux/WSL), several `isa` client tests failed with "unimplemented instruction" errors. This document details the effort to identify, implement, and verify these missing instructions to improve ISA coverage.

## Identified Missing Opcodes
Analysis of `build/logs/iaka` failures revealed the following unimplemented instructions:

### Floating Point Unit (F-Unit)
- `fprcpa` (Parallel Reciprocal Approximation, F06)
- `fclrf` (Clear Floating-Point Status Flags, F13)
- `fchkf` (Check Floating-Point Flags, F14)

### Memory Unit (M-Unit)
- `xchg` (Atomic Exchange, M16) - All sizes (1, 2, 4, 8 bytes)
- `fetchadd` (Fetch and Add, M17) - sizes 4, 8 bytes
- `flushrs`, `loadrs` (RSE Control, M25)
- `invala` variants (M24, M26)
- `fc`, `ptc.e` (Cache/TLB Purge, M28)
- `mov` to/from `psr` (Processor Status Register, M35, M36)
- `probe` (Probe Access, M38-M40)
- `itc` (Insert Translation Cache, M41)
- `sum`, `rum`, `ssm`, `rsm` (System/User Mask, M44)
- `ptc`, `ptr` (Purge Translation/Remote, M45)
- `thash`, `ttag`, `tpa`, `tak` (Translation Access, M46)

## Implementation Details

### Opcode Definitions
- Added `F_FPRCPA` to `src/lib/isa/Opcode.hpp` as it was missing despite being a variant of `frcpa`.

### Decoding Logic (`src/lib/isa/*decode*.cpp`)
- Updated `Fdecode.cpp` to correctly identify `F_FPRCPA` (Opcode 1, x=1, q=0).
- Validated that `Mdecode.cpp` already correctly decoded the M-unit instructions, but mapped them to enums that were not handled in execute.

### Execution Logic (`src/lib/isa/*execute*.cpp`)
- **Fexecute.cpp**:
  - Implemented `exec_fprcpa`: Logic mirrors `exec_frcpa` but operates on parallel register pairs (High/Low single precision).
  - Implemented `exec_fclrf`: Clears status flags in the target FPSR field.
  - Implemented `exec_fchkf`: Checks status flags and raises a fault if set (simulated as an interrupt).
  - Fixed `Fpsr` method usage (switched from non-existent `setbsfld` to `setfld`).

- **Mexecute.cpp**:
  - Implemented `exec_xchg`: Modeled as a Load followed by a Store to the same address.
  - Implemented `exec_fetchadd`: Modeled as a Load followed by a Store.
  - Implemented `exec_flushrs`, `exec_loadrs`, `exec_fc`, `exec_ptc_e`: Implemented as valid operations (NOP behavior for analyzer compatibility).
  - Implemented `exec_mov_to/from_psr`: Handles PSR reads/writes.
  - Implemented `exec_sum`, `rum`, `ssm`, `rsm`: Updates PSR bits (User Mask or System Mask) based on immediate.
  - Implemented `exec_probe`: Returns a valid probe result (1).
  - Implemented `exec_itc`, `exec_ptc`, `exec_ptr`, `exec_trans`: Implemented as valid operations.

## Verification
Re-ran `iaka` on the previously failing tests:

- **F06 (`fprcpa`)**: Passed.
- **M25 (`flushrs`)**: Passed.
- **M44 (`sum` etc.)**: Passed.
- **M17 (`fetchadd`)**: Passed decode (fails later on expected Data Access Rights fault due to null pointer, confirming instruction execution).
- **M16 (`xchg`)**: `xchg` instructions are implemented. `cmpxchg` 1/2/4 bytes remain unimplemented (only 8 byte was previously present), so the test may still fail on those specific opcodes.

## Conclusion
Significant progress was made in ISA coverage. The analyzer `iaka` can now process traces containing these instructions without aborting.

## Per-binary IA64 regression tests

- Added `scripts/generate_ia64_manifest.py` plus new CMake glue so that every prebuilt Itanium binary under `misc/clt` becomes an individual CTest target for all five clients (`iaos`, `iaka`, `iaio`, `iaoo`, `iata`). CMake now accepts either directories or the published `iato-tst-1.5.tar.gz` archive via the `IATO_IA64_TST_SOURCE` cache entry and resolves the assets during configure.
- Binaries are enumerated into `build/ia64_generated/misc_ia64_binaries.json` and converted into CTest entries named `<client>.ia64.tst.<category>.<relative_path>`, e.g. `iaoo.ia64.tst.clt.pgm.p_0005`. `iaka` runs also produce traces that the corresponding `iata` tests consume (enforced via `ctest` dependencies).
- SPEC2000 binaries are still unpacked (for documentation and future use) but are intentionally *not* wired into `ctest` to keep the suite focused on the curated `misc/clt` programs.
- Running `ctest --output-on-failure` from `build/` now executes 670 tests (131 IA64 binaries × 5 clients, plus the original 15 library/unit tests). As of commit `ba425f3`, 74 of those IA64 cases still fail with the expected traps (missing syscalls, unaligned stores, watchdogs, etc.); the failure list in the CTest summary pinpoints each offending client/binary pair for follow-up work.
